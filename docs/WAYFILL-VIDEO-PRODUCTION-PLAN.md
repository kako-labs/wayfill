# WAYFILL 영상 제작안

> 기준 러닝타임: 2분 30초 / 30fps / 16:9
>
> 말투 참고: 팀원이 제공한 `scenes (1).ts`
>
> 이 문서가 영상의 시간, 화면 행동, 자막에 대한 제작 기준이다. 기존 스토리보드보다 이 문서를 우선한다.

## 영상에서 보여줄 이야기

WAYFILL을 일부러 계속 보고 운전하는 이야기가 아니다.

1. 출발 전에 목적지와 남은 연료를 확인한다.
2. 주행 중에는 WAYFILL을 내비 옆 작은 창으로 두거나, 화면에서 닫고 백그라운드로 보낼 수 있다.
3. 중간에 주유가 필요해지면 내비 위 HUN으로 짧게 묻는다.
4. 사용자가 동의하면 내비가 실제로 경로를 바꿨는지 확인하고, 원하면 WAYFILL을 작은 창으로 다시 볼 수 있다.
5. 주유소에 도착해 주유가 확인되면 뽀동이가 반응하고, 새 연료 상태로 다시 판단한다.

## 말투 기준

- 화면에서 일어난 일을 옆에서 설명하듯 쓴다.
- 추상적인 홍보 문구보다 구체적인 행동을 말한다.
- `최적`, `스마트`, `필요한 순간`, `새로운 경험` 같은 표현은 쓰지 않는다.
- `주행을 시작해도`, `바로 안내를 고르면`처럼 원인과 결과를 한 문장에 넣는다.
- 한 화면에는 한 가지 사실만 설명한다.
- 모든 자막은 줄을 나누지 않고 한 줄로 쓴다.
- 자막에는 쉼표를 쓰지 않는다.
- 자막과 음성이 같은 문장을 반복하지 않는다.
- 기본 편집본에는 별도 내레이션을 넣지 않는다. 실제 앱의 HUN 안내 음성만 들려준다.

## 주행 중 창 상태

- `D` 전환은 WAYFILL 창을 숨기는 명령이 아니다.
- PLEOS의 앱 영역과 시스템 윈도우 조작에 따라 내비와 WAYFILL을 함께 표시할 수 있다.
- 사용자가 윈도우 배치를 바꾸거나 다른 앱으로 전환해 WAYFILL이 화면에서 밀려나면 백그라운드 상태가 될 수 있다.
- 사용자가 WAYFILL을 명시적으로 종료한 경우까지 모니터링이 이어진다고 표현하지 않는다.
- WAYFILL이 시스템 윈도우의 위치나 크기를 임의로 강제한다고 표현하지 않는다.
- 작은 창을 유지할 때는 남은 거리와 상태만 보여주고, 뽀동이는 큰 동작을 하지 않는다.
- 본편은 `작은 창 사용 가능 → 백그라운드로 전환 → HUN 수신 → 사용자가 작은 창을 다시 열 수 있음` 순서로 두 상태를 모두 보여준다.

## HUN과 음성 장면의 두 가지 편집본

### 기본 제출본

- HUN의 `바로 안내`를 손으로 누른다.
- PLEOS 내비가 실제 성공 응답을 보낸 뒤 작은 창으로 넘어간다.
- Gleo 음성 제어를 구현했다고 말하지 않는다.

### Gleo 검증본

- 실제 차량 또는 공모전 제공 환경에서 발화 인식과 액션 전달이 모두 확인된 경우에만 사용한다.
- 01:03–01:13 장면 후반에 사용자가 `응 그쪽으로 가자`고 말하는 컷을 넣는다.
- 자막은 `말로 그쪽으로 가자고 해도 바로 안내를 시작합니다`로 교체한다.
- 단순 음성 인식 데모나 녹음된 효과음만으로 구현된 것처럼 편집하지 않는다.

## 뽀동이 연출

- 출발 전: 넓고 귀여운 몸짓을 보여줄 수 있다.
- 주행 중: 작은 창에서도 가만히 호흡하는 정도만 유지한다. 반복 점프나 큰 팔 동작은 쓰지 않는다.
- HUN: 캐릭터 애니메이션보다 선택지와 내비 시야를 우선한다.
- 주유 완료: 주유량과 상태에 맞는 동작을 한 번만 재생한다.
- 기록 화면: 애니메이션을 다시 반복하지 않는다.
- `prefers-reduced-motion` 또는 차량의 감속 모드가 켜져 있으면 정지 포즈로 대체한다.

## 촬영·편집 규칙

- 30fps로 녹화하고 30fps 타임라인에서 편집한다.
- 브라우저 미리보기에서 끊겨 보여도 프레임을 건너뛴 화면 녹화로 해결하지 않는다. 최종 영상은 원본 프레임 타이밍으로 렌더한다.
- 한 자막은 기본 5–8초 유지하고 반드시 한 줄로 표시한다.
- 자막은 차량 UI 안이 아니라 영상 하단 안전 영역에 둔다.
- 화면 확대는 숫자나 버튼을 설명할 때만 쓰고, 확대가 끝나면 전체 화면으로 돌아온다.
- 실제 앱 음성이 나올 때 배경 음악을 낮춘다. 별도 내레이션과 앱 음성을 겹치지 않는다.
- 장면 전환은 디졸브 또는 짧은 컷만 사용한다. 과한 줌이나 흔들림 효과는 쓰지 않는다.
- 데모 수치는 실제 차량 기본값처럼 보이지 않도록 `예시 데이터` 표시를 유지한다.

## 최종 촬영 전에 바꿔야 하는 것

1. 팀원이 연결한 실제 PLEOS 화면의 녹화 파일명과 원본 타임코드를 장면표에 넣는다.
2. HUN 표시, 내비 경로 성공 응답, 작은 창 전환을 실제 기기에서 각각 확인한다.
3. Gleo는 인식뿐 아니라 WAYFILL 액션까지 이어지는지 확인한 뒤 포함 여부를 정한다.
4. 차량 데이터가 없을 때 `Unsupported` 또는 `Unknown`으로 멈추는 장면을 확보한다.
5. 실기 화면이 확보되기 전까지 브라우저 시뮬레이터 컷에는 `PLEOS 화면 시뮬레이션` 표기를 남긴다.
