# Motion Care 비교 후 화면 재설계

사용자가 이전 `companion-preview.html`의 알림 위치와 낮은 시각 품질을 지적했다. 이전 기능 검증을 시각 완성으로 취급하지 않는다. 이 문서는 같은 날 앞선 작은 창 구현 기록보다 뒤의 디자인 기준이다.

## 비교한 실제 자료

- Motion Care `60ffd77`의 `docs/pleos-emulator/shots/116_car_scale_home.jpg`: 큰 주 메시지·캐릭터 장면, 독립된 정보 패널, 글자 위계, 유리 질감과 공통 테두리.
- 같은 저장소 `85_guidance_card.png`: 실제 PLEOS OS 알림이 오른쪽 앱 영역의 왼쪽 상단에 표시됨. WAYFILL이나 모든 차량의 위치를 증명하는 자료는 아니다.
- PLEOS [System Notification](https://document.pleos.ai/en/docs/connect/guide/docs-design/components/notification/system-notification): OS가 제공하는 기본 알림이며 imagery/header/action 구조와 버튼 배치 선택을 설명한다. 절대 화면 좌표를 앱에 보장하는 문서로 해석하지 않는다.

## 바꾼 화면

1. **정차 홈:** 큰 설명과 캐릭터 장면, 오른쪽 추천 주유소/거리/추가 시간/행동, 아래 연료·근거·여유거리 패널로 구성했다. Motion Care의 남색/유리 깊이를 참고하고 WAYFILL의 꿀빛 금색과 캐릭터를 유지했다. 내비 자리 표시용 큰 화살표와 빈 화면은 제거했다.
2. **작은 창:** 별도 앱 창의 전체 바탕으로 구성한다. 거리 숫자와 추가 시간을 먼저 읽고, 주유소 이름과 통과 시 근거를 분리한다. 버튼은 76dp 이상이며 짧은 창은 가로로 배치한다. 주행 중에는 정지 캐릭터를 쓴다.
3. **연결 대기:** 큰 문장을 작은 캐릭터 옆에 몰아넣던 카드를 없앴다. 캐릭터, 짧은 제목/설명, 차량 연료와 경로의 확인 상태를 구분한다. 과거 거리나 가짜 0을 넣지 않는다.
4. **백그라운드 알림:** 가상의 내비 화면 오른쪽 위에 앱 전용 카드를 띄우던 미리보기를 없앴다. 알림 전달 내용만 독립적으로 보여 주고, 실제 Motion Care OS 캡처를 참고 자료로 나란히 둔다. 카드의 색/외형/위치가 그대로 PLEOS에 적용된다고 주장하지 않는다.

## 소스와 자산

- 웹 진입점은 기존 `web/companion-preview.html`을 유지했다. 처음 열면 새 정차 홈이 나온다. 조건 선택은 제품 화면 밖 검토 도구다. 하단 홈/주유 안내/기록/설정 막대는 정차 홈 디자인의 표시용 구성이다.
- Android `CompanionSurface.kt`에 공통 `FuelPilotColors`, V2 정지 초상, 작은 창/대기 화면, `FuelHomeOverview`를 둔다. `AppShell`은 같은 색과 정차 홈 패널을 사용한다. 기존 ViewModel·추천 키·내비 응답·쿨다운 계약은 바꾸지 않았다.
- `web/assets/podong-v2-calm-key.png`와 Android `podong_v2_calm.png`는 같은 파일이며 패키지 검사에서 바이트 일치를 확인한다. 기존 72프레임 운영 아틀라스와 주유 인사 타이밍은 그대로다. V2 정지 초상을 넣었다고 V2의 72프레임 애니메이션을 완성했다고 표현하지 않는다.
- 참고 OS 캡처는 `reference/motion-care-system-notification.png`다. WAYFILL 실행 화면이나 제품 이미지로 사용하지 않는다.

## 화면 검토와 한계

웹은 1440px와 420px에서 실제로 렌더해 캡처를 보고 수정했다. 큰 글자의 외톨이 줄, 긴 이름, 정보 확인 중, 주행 전환, 내비 응답 대기·실패·재시도, 미루기 후 표면 변경, 15초 무응답 종료를 확인한다. 정차 시안의 주행 가능 거리 막대는 연료 탱크 비율이 아니라 목적지 거리 대비 주행 가능 거리의 예시다.

실제 PLEOS·Devbox·실차 알림은 여전히 미실행이며, 화면 품질은 사람이 실제 크기로 직접 보고 판단해야 한다.

## 이번 변경의 검증

- `python scripts/dev.py verify`: 성공. JDK/SDK doctor, 아키텍처 검사, 빌드 및 lint를 포함한다. 전체 단위 테스트 XML은 155개, 실패·오류·건너뜀 0개다. Gradle의 UP-TO-DATE 결과는 캐시를 재사용한 것이며 모두 새로 실행했다고 해석하지 않는다.
- 마지막 밀도 조정 후 `:feature:assist:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`: 성공.
- 일반 Android API 35 에뮬레이터에서 SplitWindow 5개, VehicleScale 5개, NativeDemo 4개, SettingsMotion 1개: **15개 통과, 건너뜀 0개**. 나머지 기존 기기 테스트 7개는 이번에 실행하지 않았다.
- Node 22 문법 검사, 자산 패키지 검사, 기존 웹 상태/애니메이션 테스트 18개: 통과. 기존 테스트만으로 새 DOM의 디자인 품질을 검증했다고 보지 않는다.
- 브라우저에서 1440px/420px 렌더, 수평 넘침, 76px 버튼, 대기 화면의 행동 없음, 응답 전 성공 표시 없음, 실패 후 재시도, 미루기 유지, 시간 만료를 확인했다. 검토 작업 공간을 종료했다.
- 웹 캡처와 실제 Android 작은 창/연결 대기/정차 홈 컴포넌트 캡처를 직접 열어 확인했다. 정차 홈 컴포넌트의 단독 테스트 캡처에는 테스트 호스트의 흰 배경이 포함되며 전체 앱 화면은 아니다. 전체 앱의 외부 adb 데모 Activity 직접 실행은 비공개 Activity 정책으로 거부됐고, 이를 성공한 실행으로 세지 않는다.
