# SDK 외 제품 준비 작업 · 2026-11-11

현재 작업 브랜치는 `integrate/podong-approved`다. 승인 UI 고정 태그 `podong-ui-approved-2026-11-10`은 변경하지 않는다.

## 이번 범위

- 홈·주유 안내·설정 진입. 정차 중 여유거리 20–100km를 10km씩 변경하고 저장한 값을 판단 엔진에 전달한다.
- Application이 한 세션을 소유한다. 화면 회전과 서비스가 같은 세션을 공유하고, 다시 연결하면 저장 기록을 복원한다.
- 사용자 시작과 위치·알림 권한을 거치는 location foreground service. 중지, 권한/위치 서비스 해제, 오래된 안내 제거를 처리한다. 부팅 시에는 앱에서 재개하도록 알린다.
- 기존 경로에는 경유지 추가, 목적지가 없는 것으로 확인되면 새 목적지 설정. 요청 ID, 경로 ID, 경유지 한도, 취소와 시간 초과를 검사한다.
- debug 전용 네이티브 시연은 별도 저장소와 입력을 사용한다. release에는 시연 진입점과 합성 데이터가 없는지 DEX를 검사한다.
- Opinet 서버 경계, HTTPS 클라이언트, 캐시·쿼터·응답 검증. 공급자 거리와 실제 내비 경로 거리는 구분한다.
- Android 화면 검사, CI, 소스 전달 도구와 공모전 제안서·촬영 순서·개인정보 문서.

## 실제 연결이 필요한 부분

Pleos 차량 에너지·정차/주행·주유 이벤트와 내비 경로/응답을 연결해야 한다. 실제 차량 연료 종류, 검증된 WGS84↔KATEC 변환, 도로/경로 거리와 우회 시간 공급자가 필요하다. 이 값들이 없으면 운영 앱은 Unsupported/Unavailable을 유지한다. SDK가 없는 에뮬레이터에서 시연 숫자를 표시하지 않는 것이 정상이다.

Opinet API 사용 승인과 서버 키, HTTPS 배포 주소, 공급자 약관·표시 요건 확인은 실제 외부 설정이다. 키는 서버에만 둔다. 앱의 `-PstationGatewayOrigin=https://...`에는 공개 게이트웨이 origin만 설정하며, 이것만으로 차량/경로 연동이 완료되지는 않는다.

일반 Android 알림은 Pleos 내비 화면 위 표시 권한이나 실제 차량 UX 승인을 증명하지 않는다. 실행 중 서비스는 START_STICKY로 OS의 프로세스 복원 요청을 처리하지만, 권한·위치·저장된 사용자 선택을 다시 검사한다. 부팅·강제 중지·복원 실패에서는 앱에서 재개해야 하며 자동 생존을 보장하지 않는다. 화면 회전/런타임 복원 검사와 실제 OS 프로세스 종료 검사를 구분한다.

## 검증 기록

로컬 최종 실행은 아래와 같다. 정확한 전달 커밋, 소스 ZIP·CI 아티팩트와 원격 실행 결과는 [통합 PR #2](https://github.com/kako-labs/wayfill/pull/2)에서 확인한다. 로컬 검사와 GitHub 실행을 구분한다.

- 웹 검사: 17개 통과. 웹/Android 공통 아틀라스 72프레임 일치 검사 통과.
- 서버 검사: 9개 통과.
- Python 전달·격리·아키텍처 도구 검사: 12개 통과. Windows autocrlf가 Unix 실행 스크립트에 CRLF를 넣는 경우를 RED로 재현한 뒤 호스트 설정과 무관하게 내보내도록 수정했다.
- Android 전체 검사: `python scripts/dev.py verify` 통과. 마지막 설정 계산 경합 보완을 포함한 `verifyAll :app:assembleRelease :app:connectedDebugAndroidTest --continue --no-daemon --max-workers=1 --console=plain`도 통과했다. 단위 검사 111개, 전체 명령 534개 작업, 5분 10초.
- release 빌드와 DEX 시연 격리 검사 통과.
- Android 35 표준 AOSP 에뮬레이터에서 시스템 알림 권한 창의 거부 버튼을 눌렀다. 권한 필요 메시지를 확인했고 MonitoringService 레코드는 없었다.
- 화면 검사: Android35 AOSP/4KB 페이지, 1024×768에서 12개 통과, 실패/오류/건너뜀 0개. 홈·정차 설정·회전·목적지/경유지 성공과 실패·주유 중복·출발 중단·미지원/오래된/미수신 상태·플랫폼 JSON·모션 감소·서비스 수명주기를 검사했다.
- 프로세스 종료: 실제 foreground service를 사용자 버튼으로 시작하고 홈으로 나간 뒤 앱 UID로 프로세스를 종료했다. PID가 바뀐 새 프로세스에서 foreground service가 복원됐고 사용자 중지 버튼으로 종료됐다. 이 실험 APK는 `46fcb130…`이며 이후 시스템 표시줄 여백을 보정했다. 실제 차량 이벤트 재전달은 SDK 연결 후 별도 확인한다.

`app-debug.apk`는 설치 가능한 검토 빌드다. 정상 시작은 실제 미지원 상태이며 홈에서 별도 시연에 진입한다. `app-release-unsigned.apk`는 시연 제외 검사 빌드로, 설치·배포용 서명은 별도다. 로컬 전달 폴더와 CI 아티팩트의 `SHA256SUMS.txt`로 각각의 APK/소스 ZIP을 확인한다. 빌드 환경·서명이 다른 APK가 같은 해시라고 가정하지 않는다.

실제 네이티브 캡처: [홈](screenshots/native-home-20261111.png), [시연 추천](screenshots/native-demo-20261111.png), [정차 설정](screenshots/native-settings-20261111.png). 시연 캡처의 숫자는 합성 입력이다. 승인 아틀라스/타이밍은 유지했다.

실패 기록도 보존했다. 기존 및 새 16KB 시험 이미지에서는 Android 시스템/ART JIT 충돌로 전체 검사가 중단됐다. 표준 API35 AOSP 이미지로 바꿔 진행했다. AppOps 변경을 실제 알림 런타임 권한 거부로 간주한 초기 테스트는 올바른 검사가 아니어서 위치 해제 검사와 실제 시스템 권한 거부 관찰로 구분했다. 모션 감소 설정 화면과 시연의 미수신 상황 누락은 실제 기기 테스트 실패로 재현한 뒤 수정했다.

첫 원격 CI는 setup-android의 과거 기본값에 포함된 폐기 패키지 `tools`를 찾지 못해 테스트 전에 실패했다. 필요한 `platform-tools`와 UI job의 `emulator`만 명시하도록 수정했다. 원격 성공 여부는 PR의 실제 실행 링크를 기준으로 확인한다.

이어 `ubuntu-latest`의 Ubuntu26.04 실행 환경에서 KVM 접근 검사가 실패했다. Motion Care에서 실제 성공한 Ubuntu24.04와 임시 runner의 `/dev/kvm` 직접 권한 설정으로 맞췄다. 검사 실패를 성공으로 무시하거나 화면 검사를 건너뛰는 처리는 하지 않았다.

독립 리뷰와 회귀 검사로 실제 도로 거리(우회 포함)를 이용한 연료 여유 계산, 화면 사용 중 감시 중지의 상태 고착, 서비스 sticky 복원, 오래된 경로/계산 결과와 알림 단계 처리를 보완했다. 설정 변경 중에는 이전 설정의 계산을 버리고, 새 설정이 저장되기 전 추천/내비 요청 노출을 보류한다. 경로 후보 수집 범위가 검증되지 않으면 ‘마지막 주유 기회’로 판단하지 않는다.
