# PLEOS 실행 직전까지의 제품 작업

사용자가 2026-11-12 소프트 선셋과 도로 띠 뽀동이를 확정하고, 잠든 동안 실제 PLEOS 실행 직전까지 설계·구현·검증을 맡겼다. 이 문서는 현재 작업의 기준과 진행 기록이다. 다른 앱의 완료 항목 수가 아니라 실제 WAYFILL 경계의 재현 가능성을 목표로 한다.

## 확인한 기준

Motion Care main `60ffd77`의 `home/HomeScreen.kt`, 검증 및 emulator ledger를 비교했다. 실제 기능만 홈에 놓고, 좁은 화면과 넓은 화면을 분리하며, 실패·미지원 상태와 기기 검증을 따로 기록하는 방식을 따른다. Motion Care의 실차/PLEOS 실행 결과를 WAYFILL의 증거로 사용하지 않는다.

## 진행 순서

1. 새 캐릭터 정지 표시와 애니메이션의 간극을 해결한다. 실제로 그린 새 프레임을 사용하고 출발/Unknown/모션 감소/중복 취소 계약을 유지한다. 품질이 떨어지는 프레임을 완성이라고 부르지 않는다.
2. 승인 디자인의 홈·주유 안내·기록·설정을 실제 데이터 흐름에 연결한다. 기록에는 확인한 주유 이벤트만 넣고, 없는 주유량/가격/주유소 이름은 꾸며내지 않는다. 기록 삭제는 중복 재생 방지와 분리한다.
3. 데이터 없음·오래됨·내비 요청 대기/실패/성공·추천 미루기·새 추천의 노출 경계를 점검한다. 작은 창과 백그라운드 알림의 정보/정체성/만료를 유지한다.
4. 미실행 기존 기기 테스트의 낡은 기대를 현재 안전 정책에 맞추고 일반 Android 전체 검사를 실행한다. 필요한 회귀 검사를 추가한다. 검증되지 않은 PLEOS 어댑터는 Unsupported로 남긴다.
5. debug/release 빌드, 시연 격리, 서버/도구 검사, 소스 ZIP·해시·다음 기기 실행 순서를 만든다. 로컬 작업 브랜치에 검증한 상태를 커밋한다. 원격 push/PR/배포는 하지 않는다.

## PLEOS 기기에 남길 항목

차량 SDK 속성/권한/실제 주유 이벤트, NaviHelper 경로/경유지 응답, 차량 창 크기/시스템 알림 위치·외형·주행 UX, car-service 재시작과 실제 복원. 공급자 API 승인·키·배포 주소와 검증된 좌표/도로 거리도 실제 외부 입력이다. UI 시안이나 합성 시연으로 대신해 통과시키지 않는다.
