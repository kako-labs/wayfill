> 편집 데이터는 [`wayfill-scenes.plan.ts`](./wayfill-scenes.plan.ts)에 같은 내용으로 고정했다.

> 기준일: 2026-11-13
> 목적: PLEOS 연결 완료 후 공모전 제출·심사 설명용 2분 30초 제품 스토리 영상
> 참고 영상: 팀원이 제공한 `motioncare-story.mp4`

## 1. 참고 영상에서 확인한 구성 원칙

`motioncare-story.mp4`는 1920×1080, 30fps, H.264/AAC, 3분 10.57초 영상이며 Remotion 4.0.538로 제작됐다. 실제 Motion Care 앱 화면과 차량 호스트를 하나의 16:9 프레임 안에 두고, 기능을 나열하기보다 출발 전부터 다음 출발까지 한 번의 여정으로 설명한다.

관찰한 핵심 방식은 다음과 같다.

- 화면 아래에 여정 단계를 계속 노출하고 현재 단계만 강조한다.
- 자막은 한 장면에 한 문장, 약 5~7초, 한 줄 중심으로 유지한다.
- 앱 전체 화면을 계속 바꾸기보다 필요한 패널만 확대·딤·스크롤해 시선을 이끈다.
- 주행 중 화면은 내비 중심으로 단순하게 유지하고 시스템 카드는 필요한 순간에만 보여준다.
- 마지막에는 사용한 차량 기능, 에뮬레이터·실차 여부, 시연 데이터 범위를 구체적으로 밝힌다.
- 참고 영상의 실제 검증 결과는 WAYFILL의 증거가 아니다. 구성 방식만 참고한다.

## 2. WAYFILL 영상의 한 문장

> 가는 길과 남은 연료를 함께 보고, 놓치기 전에 가장 적절한 주유 기회를 내비에 연결합니다.

엔딩에서 반복할 네 단계는 다음과 같다.

> 경로·연료 확인 → 필요한 순간 제안 → 내비 경로 반영 → 주유 후 다시 판단

## 4. 지속 표시할 단계 레일

실제 앱 화면 아래쪽에 다음 단계를 작게 유지한다. 현재 단계만 꿀빛 금색 또는 밝은 청록으로 강조한다.

`출발 전 · 경로 판단 · 주행 · 주유 제안 · 경로 반영 · 도착/주유 · 다시 판단`

원칙:

- 도입·엔딩에서는 숨긴다.
- 모바일식 탭처럼 보이지 않도록 클릭 가능한 UI와 구분한다.
- 화면 설명용 그래픽이므로 앱 캡처 위에 영상 후반 작업으로 얹는다.
- 한 단계가 바뀔 때 색과 짧은 밑줄만 이동한다. 레일 전체를 크게 움직이지 않는다.

## 5. 캡처 출처 표기

화면 오른쪽 아래에 출처를 지속 표시한다. 아래 문구 중 실제 상태와 일치하는 하나만 사용한다.

### 현재 HTML 검토 화면

> 사전 UI 시뮬레이션 · 실제 PLEOS 화면 아님

HTML의 지도와 HUN은 외형 증거가 아니다. 이 화면을 제출 영상에 사용한다면 `예상 배치`, `시연용 데이터`도 함께 표시한다.

### PLEOS Connect 에뮬레이터에서 실제 실행한 경우

> PLEOS Connect 에뮬레이터에서 녹화한 실제 WAYFILL 화면

Virtual Console을 썼다면 별도로 다음을 표시한다.

> 차량 신호는 Virtual Console로 입력

### 실차 검증 전

> 실제 차량에서는 아직 확인하지 않음

### 시스템 HUN

> 카드 위치와 외형은 PLEOS 시스템이 렌더링

앱이 만든 HTML 카드나 임의 오버레이를 실제 HUN처럼 설명하지 않는다.

### Gleo 음성 응답

Gleo App Schema, 액션 전달과 실제 응답이 에뮬레이터 또는 기기에서 확인된 경우에만 “말로 선택” 장면을 넣는다. 미검증 상태에서는 다음처럼 표시한다.

> Gleo 연결 전 음성 흐름 시연

- [ ] 내비 성공·실패 콜백 각각 촬영
- [ ] 시연 데이터와 실제 SDK 데이터를 화면·자막에서 구분

- [ ] 1920×1080, 30fps 이상으로 녹화
- [ ] 뽀동이 애니메이션은 화면 캡처 프레임 드롭 없이 재생

- [ ] 실제 차량 내비 지도는 앱 자체 지도로 오해되지 않게 표기

## 7. 자막·편집 규칙

- 자막은 화면 아래 왼쪽에 한 줄을 기본으로 한다.
- 한 자막은 25~35자, 최대 약 42자다. 두 문장을 한 화면에 넣지 않는다.
- 5~7초 이상 읽을 시간을 준다. 숫자가 많으면 7초 이상 유지한다.
- 기능 이름보다 사용자에게 일어나는 일을 먼저 말한다.
- 한 화면 안에서 상태가 바뀌면 `요청 중`과 `반영 완료`를 별도 자막으로 나눈다.
- 확대는 추천 근거, HUN 두 행동, 내비 성공, 검증된 주유 이벤트에만 사용한다.
- 화면 전환은 짧은 딤·슬라이드 또는 6~10프레임 디졸브를 사용한다. 빠른 줌과 반복 흔들림은 피한다.
- 앱 전체가 아니라 관심 영역을 105~115%만 확대한다.
- 화면 속 시연 숫자를 영상 내레이션에서 사실처럼 일반화하지 않는다.

## 8. 오디오와 TTS

- 영상 내레이션과 앱 TTS가 동시에 말하지 않게 한다.
- HUN 등장 직전 내레이션을 0.5초 비우고 실제 앱 TTS를 들려준다.
- TTS 예시: “20킬로미터 앞 주유소에서 주유가 필요해요. 안내할까요?”
- TTS가 끝난 뒤 0.3~0.5초 후 버튼 또는 음성 응답을 보여준다.
- 내비 음성·통화·비서가 활성화된 상황에서는 WAYFILL TTS를 건너뛰는 정책을 영상 자막으로 설명하되, 실제 검증 전에는 동작 장면으로 단정하지 않는다.
- 효과음은 HUN 등장, 내비 성공, 주유 확인 세 곳에만 약하게 사용한다.
- 배경 음악은 내레이션보다 최소 16~20dB 낮게 두고, 주행 장면에서도 박자를 과하게 올리지 않는다.
- 뽀동이 동작에는 별도 캐릭터 음성을 붙이지 않는다. 시선 분산을 피하고 TTS와 역할을 구분한다.

## 9. 엔딩 검증 고지문

실제 PLEOS Connect 촬영과 Virtual Console을 사용한 경우 다음 문구를 기본으로 한다. 실제 결과에 맞게 버전과 범위를 수정한다.

> 실제 WAYFILL 앱을 PLEOS Connect 에뮬레이터에서 녹화했습니다. 차량 신호는 Virtual Console로 입력했으며, 실제 차량에서는 아직 확인하지 않았습니다. 거리·주유소·주유 이벤트 중 시연 데이터가 포함된 항목은 화면에 별도로 표시했습니다. HUN 위치와 외형은 PLEOS 시스템이 렌더링하며, WAYFILL은 추천 내용과 행동만 제공합니다. 추천은 검증된 입력이 있을 때만 생성하며, 오래되거나 지원되지 않는 값으로 대체하지 않습니다.

HTML 시뮬레이션만 사용한 사전 영상이라면 다음 문구를 사용한다.

> 이 영상은 PLEOS 연결 전 상호작용을 설명하는 UI 시뮬레이션입니다. 지도, 시스템 HUN의 위치·외형, 차량 신호와 내비 응답은 실제 기기 실행 결과가 아닙니다. 실제 PLEOS 연결과 기기 검증은 별도로 기록합니다.

## 10. 최종 촬영 전 결정할 항목

1. 버튼 선택만 촬영할지, 검증된 Gleo 음성 선택까지 포함할지.
2. HUN을 실제 시스템 카드로 촬영할 수 있는지.
3. 내비 경유지 추가 성공·실패 콜백을 어떤 테스트 경로로 재현할지.
4. 주유 이벤트를 실제 차량 신호, 에뮬레이터 테스트 포트, 명시된 시연 이벤트 중 무엇으로 공급할지.
5. 기록 탭을 본편에 둘지, 10~15초 보조 영상으로 분리할지.
6. 실차 검증 결과를 본편 엔딩에 추가할 수 있는지.

이 항목이 정해지기 전에는 영상 자막에서 실제 연결·승인·검증을 완료했다고 표현하지 않는다.
