# FUEL PILOT UI delivery Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Ship offline interactive UI, original Podong assets, a buildable Compose UI library and a next-PC handoff.

**Architecture:** Portable state-driven UI takes vehicle/navigation facts from the host app. No SDK or map overlay assumptions. Web demo uses the same motion timing and display rules; native Compose owns its independent rendering and callbacks.

**Tech Stack:** Vanilla HTML/CSS/JS, Node built-in tests, Android Compose library (AGP 8.10.1, Kotlin 2.1.20, Compose BOM 2025.04.01).

**Spec:** UI-DECISIONS.md and PODONG-BEHAVIOR.md, approved in this conversation.

## Global Constraints

- Graphite #171512, gold #E3A33C, coral #F2654E; static offline assets.
- Reason → station → action. Buttons: 여기서 주유하기 / 계속 가기.
- Large Podong only when parked. Refuel celebration once per unique event, interrupted immediately when moving. No looping or audio.
- Source GIF is reference only. Build discrete timed poses from original source art when accessible; record provenance.
- Host app supplies verified route and refuel events. Missing measurements never become invented facts.

## Review Focus

- Duplicate refuel event must not replay.
- Moving or unknown motion state must suppress celebration.
- Missing fuel liters must omit liters copy.
- Tap on recommendation invokes host callback, then waits for route confirmation.
- Saved offline bundle must open from file:// without imports, external fonts or server requirements.
