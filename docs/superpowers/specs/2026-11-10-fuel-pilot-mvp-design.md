# WAYFILL MVP 설계

## 제품 정의

WAYFILL은 연료가 이미 부족해진 뒤 주변 주유소를 나열하는 앱이 아니다. 활성 내비게이션 경로와 남은 주행 가능 거리를 함께 보고, 운전자가 주유하기 좋은 마지막 안전 기회를 지나치기 전에 한 번만 알려 주는 Pleos 차량 앱이다.

> 연료가 부족해진 다음이 아니라, 주유하기 좋은 마지막 기회를 놓치기 전에.

## 선택한 접근

합성 데이터로 Android 전체 흐름을 먼저 완성하고 실제 SDK를 교체 가능한 adapter로 연결한다. demo 빌드는 합성 에너지·경로·POI·내비 구현을 명시적으로 사용한다. 실제 입력이 실패하면 합성값으로 조용히 대체하지 않고 미지원 또는 오류를 표시한다.

Pleos 실연동만 먼저 구현하는 방법은 CAR_ENERGY 승인, 대상 차종 지원, 공개 POI 검색 API가 불확실해 중심 접근에서 제외한다. HTML은 정보 구조를 검토하는 일회성 시안이며 제품 코드로 옮기지 않는다. UI는 밝은 B안의 정보 위계만 임시 참고하고 나중에 다시 디자인한다.

## 목표

1. RANGE_REMAINING과 사용자 최소 잔여거리로 목적지 도착 여유를 계산한다.
2. 경로상 주유소를 순서대로 평가해 마지막 안전 주유 기회를 찾는다.
3. 목적지가 없으면 주변 후보를 유종·영업·거리 순으로 추천한다.
4. 후보 1곳과 대안 최대 2곳을 지도 없이 표시한다.
5. 추천마다 계산 사실에 근거한 쉬운 한 줄 이유를 표시한다.
6. 확인 한 번 뒤 내장 내비 경유지 전달 결과를 성공·실패·미지원으로 구분한다.
7. 합성 데이터와 실제 데이터를 모든 계층에서 구분한다.

## 비목표

- 앱 내부 지도, 지도 SDK, 경로선 또는 턴 안내 렌더링
- 연료 가격 비교, 결제, 주유 예약
- EV 충전 계획
- 교통·경사·공조를 반영했다고 주장하는 정밀 소비 예측
- 외부 API 키를 APK에 포함
- 내비 콜백 전에 경유지 추가 성공으로 표시

## 핵심 흐름

### 활성 목적지가 있을 때

1. 에너지, 위치, 목적지, 남은 거리와 경유지 수를 읽는다.
2. MVP에서는 현재 주행 가능 거리에서 목적지까지 남은 거리를 빼 도착 예상 잔여거리를 계산한다.
3. 예상 잔여거리가 사용자 목표 이상이면 조용히 대기한다.
4. 목표보다 작으면 경로상 유종 호환·영업 가능 후보를 평가한다.
5. 후보 도착 시 예상 잔여거리가 목표 이상인 후보 중 가장 뒤의 후보를 마지막 안전 기회로 본다.
6. 마지막 안전 후보가 알림 범위에 들어오면 추천한다.
7. 사용자가 확인하면 내장 내비에 경유지로 전달한다.

이 계산은 교통·경사·공조·주행 습관을 반영하지 않는 MVP 거리 차감 모델이며 화면에 추정임을 표시한다.

### 활성 목적지가 없을 때

1. 현재 위치 기준으로 도달 가능한 주변 후보를 조회한다.
2. 유종 호환과 영업 상태를 우선하고 가까운 순으로 최대 3곳을 표시한다.
3. 추천 이유는 “현재 위치에서 가장 가깝고, 영업 중이며, 유종이 맞아요.”처럼 표시한다.
4. 확인하면 내장 내비에 목적지 또는 경유지로 전달한다.

## 최소 잔여거리

- 기본값은 50km다.
- 사용자는 정차 중에만 20~100km를 10km 단위로 설정한다.
- 제품 설정일 뿐 안전 기준이나 저연료 경고 임계값으로 표현하지 않는다.

## 추천 순서와 한 줄 이유

추천 순서는 도달 가능성, 유종 호환, 영업 상태, 마지막 안전 기회, 경로 이탈 시간, 목적지가 없을 때 현재 거리 순이다.

예시:

- 이곳을 지나면 설정한 50km 여유를 지키기 어려워요.
- 다음 안전 주유 기회 전, 현재 경로에서 가장 적게 벗어나요.
- 현재 위치에서 가장 가깝고, 영업 중이며, 유종이 맞아요.
- 영업 정보가 오래되어 출발 전에 확인이 필요해요.

이유는 계산에 사용한 사실만 말한다. 경로 계산값이 없으면 우회 시간이나 경로 이탈 근거를 만들지 않는다.

## 상태

- Monitoring: 추천 없이 감시
- LoadingContext: 에너지·위치·경로·POI 조회
- NoAction: 도착 예상 여유가 충분함
- CandidatesReady: 지도 없는 후보 목록
- Confirming: 운전자 한 번 확인
- Submitting: 내비 콜백 대기와 중복 탭 차단
- Delivered: 내장 내비 전달 완료와 전환
- Unavailable: 권한 거부, 차량 속성 미지원, 위치 없음, POI 실패, 경유지 2개, 내비 실패

오래된 값은 최신 값처럼 사용하지 않는다. 영업 정보가 오래되면 폐점으로 추정하지 않고 확인 필요로 표시한다.

## 데이터 계약

- EnergySignalRepository: RANGE_REMAINING, 지원·권한·관측 시각과 출처
- VehicleLocationRepository: 위치, 정확도, 관측 시각과 출처
- FuelPoiRepository: 위치·경로·유종에 맞는 후보와 공급자·최신성
- NavigationRouteRepository: 목적지·남은 거리·경유지·capability 조회와 경유지 전달

화면과 ViewModel은 SDK·DB·HTTP를 직접 호출하지 않는다. 구현은 internal로 숨기고 Repository만 공개한다.

## Pleos 확인 수준

- 확인됨: AAOS RANGE_REMAINING과 Virtual Console Energy 카드 재현 근거
- 확인됨: NaviHelper 목적지·경유지 조회와 경유지 추가 계열 API
- 조건부: CAR_ENERGY, NAVI_ROUTE, NAVI_ROUTE_SEARCH 승인과 차종별 지원
- 조건부: 최대 경유지 2개와 콜백 기반 최종 성공
- 미확인: Pleos 공개 주유소 POI 검색 API
- 미확인: 외부 앱이 얻는 전체 경로 형상과 후보별 정확한 우회 시간

첫 실연동 검증 질문:

> Pleos에서 남은 주행 가능 거리와 활성 내비게이션의 목적지·남은 거리를 동시에 안정적으로 읽을 수 있는가?

## 모듈

    app                 앱 진입점, Navigation, 의존성 조립
    core:model          순수 Kotlin 모델과 판단 입력·결과
    data:energy         AAOS 또는 합성 에너지 Repository
    data:location       Pleos 또는 합성 위치 Repository
    data:poi            외부 공급자 또는 합성 POI Repository
    data:navigation     NaviHelper 또는 합성 내비 Repository
    feature:assist      ViewModel, 판단 엔진, Compose UI, navigation graph

## 화면

1. 감시 홈: 주행 가능 거리, 목적지 유무, 최소 여유
2. 추천 카드: 추천 주유소와 한 줄 이유
3. 후보 목록: 지도 없이 최대 3곳 비교
4. 확인: 선택 지점과 내비 전달 한 번 확인
5. 결과: 내장 내비 전달 성공·실패·미지원
6. 정차 설정: 최소 잔여거리 변경

주행 중에는 한 번에 하나의 판단만 요구하고 입력과 긴 설명을 숨긴다.

## 구현 판단

- 패키지는 dev.fuelpilot, 앱 이름은 WAYFILL이다.
- 첫 릴리스는 합성 demo 전체 흐름과 실제 adapter 계약을 포함한다.
- 실제 POI와 NaviHelper 전달은 승인·약관·실측 전까지 feature flag 뒤에 둔다.
- UI는 B안의 밝은 정보 위계를 임시 사용하되 지도는 표시하지 않는다.

## 구현 정책 보완

- 활성 목적지가 있을 때는 경로 기반 마지막 안전 주유 기회 판단을 우선한다.
- 활성 목적지가 없을 때만 현재 위치 기준 일반 주변 주유소 추천으로 전환한다.
- 거리 표시는 정수 km로 반올림하되 계산에는 Double 값을 유지한다.
- 주변 추천 후보는 현재 주행 가능 거리 안에 있고 차종 연료와 호환되는 곳만 사용한다.
- 영업 상태는 Open, Closed, Unknown으로 구분한다. 오래된 영업 정보는 Unknown으로 낮추고 추천 이유에 출발 전 확인이 필요함을 표시한다.
- 데이터 신선도 기본값은 에너지 10초, 위치 30초, 경로 30초, 영업 정보 30분이다. 임계값은 FreshnessPolicy로 주입한다.
- 마지막 안전 주유소 알림은 후보까지 20km 이내 또는 도착 예상 15분 이내일 때 노출한다. 시간 자료가 없으면 거리 기준만 사용한다.
- 동일한 활성 경로에서는 routeId와 stationId 조합당 한 번만 알린다. 목적지가 바뀌면 억제 기록을 초기화한다.
- 내비 전달 요청은 requestId로 콜백을 연결하고 제한 시간 안에 성공 콜백을 받은 경우에만 Delivered로 표시한다.
- NavigationRouteRepository는 새 목적지 설정과 기존 경로의 경유지 추가를 별도 계약으로 제공한다.
- 차량 정차 여부는 VehicleMotionRepository로 조회하며 최소 여유거리 설정은 정차 중에만 변경한다.
- 합성 데모는 NoAction, LastSafeStop, Nearby, Stale, NavigationFailure 시나리오를 제공한다.
- 추천 이유는 실제 입력으로 확인한 사실만 한 줄로 표현한다. 경로 또는 우회 계산이 없으면 관련 표현을 만들지 않는다.
