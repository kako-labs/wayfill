# 제품 준비 독립 리뷰 기록

기준: `f7b576f` 이후 제품 준비 변경. 별도 리뷰어가 설정·저장·런타임·서비스·내비 요청·공급자 서버/클라이언트·시연 격리·CI/전달 도구를 읽었다. 리뷰어는 Gradle을 중복 실행하지 않았고 서버 9개와 Python 도구 11개 검사만 독립 실행했다. Android 결과는 통합 세션의 실제 실행 기록으로 판단한다.

| 발견 | 조치와 회귀 확인 |
| --- | --- |
| 경로 진행 거리가 실제 주유소 접근 거리보다 짧으면 연료 여유를 과대평가 | 실제 도로 거리로 도착 잔여/안전 후보 계산. 우회 35km/85km의 RED 2개 확인 후 수정 |
| 화면 사용 중 감시만 끄면 Unknown으로 고착 | UI/서비스의 공유 활성 조건이 중단을 소유하도록 수정. 화면이 활성일 때 정차 입력 유지 검사 |
| 성공한 서비스가 sticky 복원을 요청하지 않음 | 성공 경로 START_STICKY, 권한/조건 실패는 NOT_STICKY. 저장 복원 후 SDK 구독 유지 |
| 독립적으로 읽은 위치/경로와 POI 계산 문맥 불일치 | 같은 위치·경로를 contextual query로 전달하고 실제 도로 계산 전후 문맥 확인 |
| 알림 단계와 내비/주유 중 상태 구분 부족 | 추천/지나치기 전 단계별 키, pending/refuel 제외, 무효 상태와 화면 복귀 시 알림 제거 |
| 설정 화면만 모션 감소 전달 누락 | 실제 Android에서 프레임 변화로 RED 재현. 설정 진입에도 동일한 정지 정책 전달 |
| 시연 미수신 상황/새 목적지 응답 검사 부족 | 명시적 unavailable 시연과 실제 목적지 요청 완료까지 화면 검사 확장 |

부모 통합 검토에서는 설정 변경 중 늦은 이전 계산, 저장 전 기존 추천 키 재사용, 경로 수집 범위의 누락도 보강했다. 계산 설정값을 intent에 붙여 불일치 결과를 버리고, 정책 저장 전에는 긍정적 노출을 보류한다. 실제 경로 후보 수집 범위 검증은 별도 포트 계약이며 가까운 원시 POI 목록만으로 충족하지 않는다.

외부 미검증: 실제 Pleos 차량/API와 지도 표면 권한, Opinet 승인/키/HTTPS 배포, 검증된 좌표 변환, 실제 도로/경로 후보 수집과 차량에서의 성능·복원. 이 리뷰는 해당 항목의 완료를 주장하지 않는다. 최종 결과는 [제품 준비 기록](product-readiness-2026-11-11.md)과 제출 체크리스트를 참조한다.
