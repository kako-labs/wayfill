# 내비 옆 작은 창과 백그라운드 주유 안내

**후속 디자인 기준:** 사용자 피드백 후 [화면 재설계](REDESIGN-2026-11-12.md)를 적용했다. 이전 갈색 카드와 오른쪽 위에 고정한 웹 알림 배치는 최신 디자인이 아니다.

2026-11-12 후속. 시작점 `94d0c7d`, 작업 브랜치 `ui/adaptive-companion-20261112`.

## 제품 판단

Motion Care 통합에서 반복된 공통 스타일·차량용 터치 크기·긴 문구·화면 간 계산 일치를 WAYFILL에 적용한다. WAYFILL은 운행 기록 앱이 아니라 경로상 주유 기회를 알려 주므로, 작은 창에는 추천 이유 → 추천 주유소 → 경로 거리·추가 시간 → 행동 순서만 남긴다. 지도를 자체 구현하거나 다른 앱 위에 앱 창을 강제로 띄우지 않는다. 차량이 허용하는 나뉜 앱 창과 OS 알림은 다른 표면이다.

| 상황 | 표시와 행동 |
| --- | --- |
| 정차·넓은 앱 창 | 기존 추천·분석·설정·주유 완료 화면. 승인된 캐릭터 동작 유지 |
| 내비 옆 작은 앱 창 | 실제 앱 bounds가 폭 760dp 미만 또는 높이 480dp 미만이면 간단한 추천. 긴 이름이 버튼 폭을 빼앗지 않도록 캐릭터/제목, 주유소, 거리, 행동을 별도 행에 배치 |
| 작은 창·정차 | 홈에서 유효한 추천이 있으면 대시보드보다 추천과 행동을 먼저 표시. 설정은 정차 탭에서 접근 |
| 작은 창·주행 | 차분한 정지 포동이. 스크롤·분석·설정·주유 축하 없이 바로 안내/나중에 두 행동. 좁은 창은 세로 버튼, 짧은 창은 가로 버튼 |
| 상태 미확인 또는 오래된/미지원 데이터 | 안내 버튼 없음. 오래된 거리를 현재 값처럼 노출하지 않음 |
| 앱이 뒤로 감 | 모니터링 동의·권한·유효한 추천이 있을 때 OS 알림. 앱 숨김 자체도 관찰하므로 새 차량 표본을 기다리지 않음 |
| 알림 행동 | 현재 추천 키·주유소 ID 검증 후 기존 런타임으로 요청. SDK 응답 전에는 성공을 표시하지 않음 |
| 앱에서 추천을 미룸 | 같은 추천을 앱 숨김만으로 다시 알리지 않음. 기존 알림 쿨다운 15분과 무응답 15초 종료는 별개 |
| 정차에서 출발 | 이전 추천과 대기 중인 내비 요청을 무효화. 새 주행 평가 뒤에만 행동 가능한 추천을 다시 수신 |

760/480dp 전환점, 좁은 창 24/26sp 본문, 넓은 창 32sp 및 보조 24sp, 최소 76dp 행동 버튼은 이번 제품/배치 판단이다. 모든 화면과 실차에서 검증된 표준값이라고 주장하지 않는다. 아주 작은 창·큰 시스템 글꼴·실제 PLEOS 다중 창은 추가 확인이 필요하다.

## 공통 근거와 문구

`FuelRecommendationCopy.kt`에서 앱과 알림의 짧은 추천 이유·주유소 이름·경로 거리·추가 시간을 만든다. 통과 경고는 다음 주유소까지의 거리와 주행 가능 거리가 모두 유효하고 실제로 부족할 때만 사용한다. 값이 없거나 NaN/음수이면 0이나 마지막 안전 기회로 바꾸지 않는다. 경로 +0분은 유효하다. 알림 본문은 거리·추가 시간을 먼저 넣어 긴 이름 때문에 잘리지 않게 한다. 긴 이름은 화면에서 생략될 수 있으나 요청에는 원래 station ID를 쓴다.

출발 시 기존 `MotionChanged`가 노출 기록을 지운 직후 남아 있던 정차 presentation을 다시 노출하던 실패도 수정했다. 기존 `departureClearsPendingAndExposureAndIgnoresItsCallback` 테스트에 추천 무효화 검증을 보강했다. 앱 헤더의 Compose 범위 수신자와 알림 기록 Set의 `takeLast` 컴파일 오류도 수정했다.

## 검토 방법

`web/companion-preview.html`을 파일로 열면 작은 창/넓은 창/백그라운드, 주행/정차/미확인, 오래된 정보, 긴 이름을 비교할 수 있다. 새 추천과 내비 성공·실패 응답은 시연 조작이다. 차량 내비 영역은 자리 표시이며, 알림은 HTML 그림으로 실제 OS HUN이 아니다. 기존 운영 아틀라스의 차분한 첫 프레임을 사용한다.

Android의 실제 연결은 `FuelPilotUi`, `AppShell`, `MonitoringService`와 공유 런타임을 사용한다. MainActivity에 나뉜 창을 위한 resizeableActivity와 distractionOptimized를 명시했다. Motion Care에서 확인했던 주행 시 시스템 차단을 피하기 위한 선언이며, 앱이 주행 제약을 직접 지켜야 한다. 주행/미확인 상태는 상세·설정·큰 동작을 차단한다. 이 선언만으로 PLEOS 실행이나 심사 승인을 증명하지 않는다. 운영 SDK/권한/검증된 주유소·내비 대상이 없으면 계속 Unsupported다. 이번 웹 시연을 운영 차량 데이터나 PLEOS 알림 승인 근거로 삼지 않는다.

검증 결과는 `verification-adaptive-2026-11-12.md`에 별도로 기록한다. 정지 캡처와 자동 테스트 외에 사람이 실제 크기의 화면을 직접 보고, 실제 PLEOS에서 알림과 내비 전환을 확인해야 한다.
